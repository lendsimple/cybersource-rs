# cybersource

[![crates.io](https://img.shields.io/crates/v/cybersource.svg)](https://crates.io/crates/cybersource)
[![docs.rs](https://docs.rs/cybersource/badge.svg)](https://docs.rs/cybersource)
[![CI](https://github.com/lendsimple/cybersource-rs/actions/workflows/ci.yml/badge.svg)](https://github.com/lendsimple/cybersource-rs/actions/workflows/ci.yml)

An idiomatic Rust client for the [Cybersource REST API](https://developer.cybersource.com/api-reference-assets/index.html),
with async, blocking and WebAssembly support.

- **The whole API:** all 220 operations and 2,068 models, generated from
  the spec in Cybersource's official SDKs. Each API area sits behind its
  own feature flag.
- **Authentication:** JWT (shared secret, RSA key or P12) and legacy HTTP
  Signature. Signatures match the official SDKs byte for byte.
- **Message-level encryption** of requests and responses (JWE).
- **Macros** for request bodies: `build!`, `payment!`, `capture!`, `refund!`,
  plus compile-time checked amounts and currencies.
- **Safe defaults for money:** declines are outcomes, not errors.
  "Outcome unknown" failures are flagged, and money-moving calls are
  never retried automatically.
- **Helpers:** pagination, ETags, capture-context and transient-token
  verification, webhook signatures, and `tracing` with card and personal
  data redacted.
- **Runs on** tokio or any other executor, blocking threads, Cloudflare
  Workers, Deno, Node and WASI 0.2.

## Quick start

```toml
[dependencies]
cybersource = "0.1"
tokio = { version = "1", features = ["macros", "rt-multi-thread"] }
```

```rust,no_run
use cybersource::flows::PaymentOutcome;
use cybersource::{Client, Config, Credentials, Environment, payment};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let config = Config::builder()
        .environment(Environment::Sandbox)
        .merchant_id("your_merchant_id")
        .credentials(Credentials::jwt_shared_secret("key-id", "base64-shared-secret")?)
        .build()?;
    let client = Client::new(config);

    let response = client
        .payments()
        .create_payment(payment! {
            code: "order-1",
            amount: "49.99" USD,
            card: { number: "4111111111111111", expiration_month: "12", expiration_year: "2031" },
            bill_to: {
                first_name: "John", last_name: "Doe", address1: "1 Market St",
                locality: "San Francisco", administrative_area: "CA", postal_code: "94105",
                country: "US", email: "test@cybs.com", phone_number: "4158880000",
            },
        })
        .await?;

    // Declines are HTTP 201 too: read the outcome from the body.
    let outcome = PaymentOutcome::from(&response);
    println!("{:?}: approved = {}", response.id, outcome.is_approved());
    Ok(())
}
```

More in [`examples/`](examples): authorize and capture, the blocking
client, TMS customers, capture contexts and webhooks. They run against
Cybersource's public sandbox merchant as they stand:
`cargo run --example authorize_and_capture`.

## Targets and features

| Target | Transport | Feature |
|---|---|---|
| Native, async | `ReqwestTransport` | `reqwest` (default) |
| Native, blocking | `UreqTransport` | `ureq` |
| Cloudflare Workers, Deno, Node (wasm32) | `FetchTransport` | `fetch` |
| WASI 0.2 (`wasm32-wasip2`) | `WasiTransport` | `wasi` (Rust 1.91.1+) |
| Anything else | implement `HttpTransport` | |

- **API groups:** `payments`, `tms` and `capture-context` are on by
  default. `full` enables every group; the full list is in `Cargo.toml`.
- **TLS:** `rustls` (default) or `native-tls`.
- **Other features:**
  - `p12` (default) loads P12 key files.
  - `http-signature` enables legacy auth.
  - `tracing` adds request spans.
  - `rust_decimal` adds conversions for amounts.

**Web checkouts:** card data should not touch your page. Use
Cybersource's Microform or Unified Checkout. This crate creates their
capture contexts and verifies the tokens they return. Cybersource rejects
Flex API tokenization from browsers. Native clients can tokenize
directly with the `flex` module, which needs no features and no
credentials.

MSRV: Rust 1.88.

## Development

```sh
cargo nextest run --workspace --all-features   # tests
cargo xtask check-codegen                      # src/generated matches the spec
CYBS_LIVE=1 cargo nextest run --all-features --test live_sandbox --run-ignored only
```

The code in `src/generated/` is generated by `cargo xtask codegen` from
`spec/`, which comes from the official Python SDK; `spec/SOURCE.md` records
the exact version. `implementation.md` describes the design.
